2) CGPA PREDICTION  POST /api/v1/cgpa/predict
--------------------------------------------------------------------------------
Request  (Content-Type: application/json):
{
  "roll_no": "210029023375"
}

Response 200 (real sample):
{
  "predicted_grade": 6.27,
  "confidence_score": 81.7,
  "confidence_display": "81.7%"
}

Field meaning:
  predicted_grade   -> predicted final grade (0-10 scale)
  confidence_score  -> model confidence (0-100)
  confidence_display-> ready-to-show string, e.g. "81.7%"

Errors:
  404  {"detail": "..."}  student not found
  503  {"detail": "..."}  model file not available

--------------------------------------------------------------------------------
2b) RISK PREDICTION  GET /api/v1/risk/{roll_no}
    (or POST /api/v1/risk/predict  body: {"roll_no": "..."})
--------------------------------------------------------------------------------
The student is fetched from the database and scored by six per-subject XGBoost
classifiers. Response 200 (sample):

{
  "roll_no": "210029023375",
  "full_name": "Aarav Rao",
  "class_section": "CS-DS",
  "risk_count": 4,
  "at_risk_subjects": ["coa", "ds", "python", "cyber"],
  "predictions": [
    {
      "subject": "coa",
      "label": "Computer Organization & Architecture",
      "probability": 0.71,
      "threshold": 0.4,
      "prediction": 1,
      "status": "At Risk"
    },
    { "subject": "maths4", "label": "Mathematics IV", "probability": 0.31,
      "threshold": 0.35, "prediction": 0, "status": "Safe" }
    // ... one entry per subject: coa, maths4, dstl, ds, python, cyber
  ]
}

Field meaning:
  prediction  -> 1 = at risk, 0 = safe
  status      -> "At Risk" / "Safe" (ready to show)
  probability -> model probability (0-1); threshold = tuned decision cut-off

Errors: 404 student not found, 503 risk model file not available.

5) STUDENTS  (full CRUD)
--------------------------------------------------------------------------------
5a) ADD / UPDATE A STUDENT   POST /api/v1/students
    Request: minimum {"roll_no": "210029099999"}
    Any other dataset column is accepted (102 possible columns, e.g.
    full_name, class_section, previous_cgpa, coa_st1_marks, ... - all stored).
    If the roll_no already exists, the row is UPSERTED (fields updated).
    IMPORTANT: mentor is auto-assigned in the background and saved to the DB.
    Response 200: the full stored student row (102 keys).

5b) UPDATE PARTIAL   PUT /api/v1/students/{roll_no}
    Request: send ONLY the fields to change, e.g.
    {"full_name": "Aarav R.", "coa_st1_marks": 15.0}
    Response 200: updated full row.         400 if body is empty.

5c) LIST STUDENTS   GET /api/v1/students?limit=50&offset=0
    limit  : 1-500 (default 50)
    offset : >= 0 (default 0)
    Response 200 (real sample):
    {
      "count": 1,
      "total": 1999,
      "limit": 50,
      "offset": 0,
      "students": [ { "roll_no": 210029023375, "full_name": "Aarav Rao", ... 102 keys } ]
    }
    use "total" for pagination, "students" for the page rows.

5d) GET ONE STUDENT   GET /api/v1/students/{roll_no}
    Response 200: the full row (102 columns).
    Note: roll_no may come back as a NUMBER (not a string) - handle both.

5e) DELETE   DELETE /api/v1/students/{roll_no}
    Response 200: {"deleted": "210029099999"}
    Also removes the student's mentor assignment rows.

    Errors: 400 invalid body, 404 student not found.

--------------------------------------------------------------------------------
6) ERROR FORMAT (all endpoints)
--------------------------------------------------------------------------------
Every error returns the FastAPI standard shape:
  { "detail": "human readable message" }
Status codes seen: 400 (bad body), 404 (not found), 503 (model/engine issue).

--------------------------------------------------------------------------------
7) TIPS FOR THE FRONTEND DEV
--------------------------------------------------------------------------------
- Add "Content-Type: application/json" on POST / PUT requests.
- First /mentor call can take ~5 seconds (engine fits once) - afterwards fast;
  show a small loading state on the mentor screen.
- risk_level values: "Need Help", "Fell Down", "Normal", "Topper"
  (priority_rank 1..4 matching that order).
- A student "card" on the dashboard needs: roll_no, full_name, class_section,
  predicted CGPA (/cgpa/predict), risk_level + priority_rank (/mentor/{id}).
- The text report (/report) is great for a print/download button.
- For search by name use  GET /api/v1/mentor/{full name}  or  /mentor/analyze.
- To show weakness: iterate subjects + labs where mentor_needed == true, show
  weak_units / weak_parts, and the recommended mentor + peer mentor.
